# MLflow Removal and Custom Persistence Review

**Decision:** remove MLflow from the maintained dependency and API surface  
**Reviewed:** 2026-08-04, against `main` at `2b5d41c` plus the hardening changes described here  
**Release boundary:** `agent-compaction` 0.6.0  
**Related decision:** [ADR 0010](architecture/0010-single-framework-adapter.md)

## Executive verdict

MLflow was not earning its complexity in this repository. The former adapter contained
338 lines, added a large optional dependency and a version-compatibility surface, but no
compiler, experiment, demonstration, paper analysis, or runtime path consumed its trace
query/visualization functionality. The only broadly used functions in that module were
`read_jsonl` and `write_jsonl`; both were standard-library JSON functions unrelated to
MLflow. The OpenAI Agents SDK processor is the actual framework-to-IR capture path.

The clean design is therefore:

```text
OpenAI Agents SDK spans -> Agents SDK adapter -> typed Episode IR
                                                |
                                                +-> canonical local JSONL snapshot
                                                +-> compiler/evaluation/registry
```

The replacement is intentionally not a home-grown experiment-tracking platform. It owns
only the persistence properties the repository actually needs: deterministic encoding,
atomic snapshot replacement, strict JSON, streaming reads, duplicate-identity rejection,
and source-line diagnostics. Existing manifests, content digests, artifact registries,
and the hash-chained `RunLedger` continue to own provenance, artifact lifecycle, and
resumable study evidence. Reimplementing MLflow search, dashboards, SQL tracking, or
remote collaboration would be unjustified.

## Repository evidence

The decision was made from code and artifact use, not dependency size alone.

| Question | Observed evidence | Conclusion |
|:---|:---|:---|
| Did any optimizer import MLflow? | No imports in `graph/`, `grc/`, `tgws/`, `portfolio/`, `evaluation/`, or `runtime/` | Removal does not change algorithms |
| Did experiments or paper scripts load from MLflow? | No; maintained workflows use committed JSON/JSONL/CSV artifacts and typed `Episode` objects | No experimental claim depends on MLflow |
| Was MLflow the runtime tracer? | No; `capture/agents_sdk.py` is the implemented foreign-trace adapter | Agents SDK integration remains intact |
| Was the former adapter exercised? | Two MLflow-specific integration tests covered an SQLite round trip and version pin; no application called it | Tested code was isolated, not an operational dependency |
| What did public examples use? | `ac.read_jsonl("traces.jsonl")` and `ac.write_jsonl(...)` | Moving these names preserves the common API |
| What does the paper evidence require? | Frozen local artifacts, manifests, native SDK trace IDs, and release validators | Local deterministic persistence is sufficient |

At the pre-removal commit `a024cbd`, the adapter exposed configuration, export, search,
load, and flush helpers. Repository-wide reference analysis found those MLflow-specific
functions only in the adapter, its smoke branch, and its two dedicated tests. By contrast,
the JSONL names were used by the CLI, README, synthetic fixtures, and API integration
tests. This is a strong cohesion signal: JSONL was the real persistence abstraction and
had merely been placed in the wrong module.

## Replacement design

`capture/jsonl.py` is an immutable-snapshot store for the compiler IR:

- canonical UTF-8 JSON (`sort_keys`, compact separators, Unicode preserved);
- strict numeric/data semantics (`NaN`, infinities, and arbitrary Python objects fail
  rather than being silently converted with `default=str`);
- write-to-sibling-temp, file `fsync`, atomic `os.replace`, and directory `fsync` where
  supported;
- preservation of the last valid target if iteration or serialization fails;
- line-by-line reads rather than loading the complete corpus text at once;
- path and line number in malformed-record errors;
- top-level object and unique `episode_id` enforcement on both write and read.

These properties close correctness gaps in the first 43-line replacement, which used a
non-atomic overwrite, loaded the entire file, silently stringified unsupported values,
and accepted ambiguous duplicate identities. The public `read_jsonl`/`write_jsonl`
names and on-disk newline-delimited object shape remain compatible for valid existing
files. Canonical output bytes change, so code that improperly depended on whitespace or
key order must compare parsed records or content generated by one release.

### Responsibility boundary

| Need | Current owner | Why it does not belong in the JSONL store |
|:---|:---|:---|
| Foreign trace normalization | `capture/agents_sdk.py` | Framework-specific mapping |
| Episode persistence | `capture/jsonl.py` | Small, local, deterministic snapshot |
| Execution compatibility | `ExecutionManifest` | Semantic identity, not file storage |
| Study resume/integrity | hash-chained `RunLedger` | Append/idempotency semantics differ from a snapshot |
| Artifact promotion/rollback | `registry/` | Lifecycle and signature policy |
| Dataset/artifact checksums | benchmark and publication manifests | Cross-file evidence integrity |
| Fleet-wide trace search/UI | external observability chosen by adopter | Not used or validated by this project |

## Complexity and capability trade-off

| Dimension | Former MLflow backend | Custom local store | Effect |
|:---|:---|:---|:---|
| Maintained adapter code | 338 lines plus compatibility logic | focused standard-library module | smaller review surface |
| Dependency | `mlflow>=3.14,<4` optional extra and transitive stack | Python standard library | simpler install and release matrix |
| Canonical replay input | Explicitly could not trust truncated trace previews | exact typed IR records | better fit for compiler evidence |
| Atomic local snapshot | Not provided by adapter | provided | stronger local failure behavior |
| Remote SQL search/UI | provided | not provided | deliberate capability loss |
| Multi-user experiment tracking | provided | not provided | use an external system only when an adopter needs it |
| Second vendor mapping evidence | provided in prototype form | absent | framework-neutrality is architectural, not yet demonstrated by two live adapters |

Removal does **not** imply that MLflow is a poor observability product. It means the
repository did not use enough of it to justify owning and certifying an integration.
An adopter may independently export SDK/OpenTelemetry traces to MLflow while supplying
complete `Episode` records to this library. Such an exporter is outside the compiler's
trusted replay path.

## Compatibility and migration

The package advances from 0.5.0 to 0.6.0 because pre-1.0 public MLflow-only names
(`capture.configure`, `available`, `export_episodes`, `load_episodes`, and `flush`) are no
longer present. The dominant API remains source-compatible:

```python
import agent_compaction as ac

episodes = ac.read_jsonl("traces.jsonl")
ac.write_jsonl(episodes, "normalized.jsonl")
```

Applications that called the removed backend should capture through the Agents SDK
processor and persist normalized episodes locally. If remote search is an actual product
requirement, keep that observability integration in the application and add a narrow,
tested `TraceSource -> Episode` adapter rather than making the compiler depend on it.

## Validation gates

bytes, atomic failure, strict/non-finite JSON rejection, duplicate identity, blank lines,
malformed line diagnostics, absence of third-party imports, and Agents SDK runtime
conformance. The release audit also rejects a reintroduced MLflow extra, source adapter,
wheel member, or wheel dependency. Final repository, paper, and package results are

## Residual limitations and recommendation

1. JSONL is a local snapshot, not a concurrent database. Writers must publish whole
   snapshots; use `RunLedger` for resumable append-only studies.
2. Atomic replace protects readers and the previous snapshot, but it does not coordinate
   multiple competing writers. A higher-level job lock is required for shared paths.
3. The reader returns a list after streaming validation because downstream APIs currently
   require sequences. Very large corpora may later warrant an iterator API and external
   sort/partitioning, based on measured memory pressure.
4. Removing MLflow leaves only one implemented foreign trace adapter. Add a second adapter
   only when a real integration and conformance corpus exist; do not add a speculative
   dependency merely to strengthen a framework-neutrality claim.

**Recommendation:** keep MLflow removed. The custom code is smaller, more deterministic,
and more faithful to the actual evidence pipeline. Reconsider a remote tracking adapter
only after a concrete adopter requires server-side search or multi-user tracking and is
willing to maintain the corresponding compatibility, privacy, and conformance tests.
