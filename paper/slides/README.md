# Publication slide generation

The canonical seminar and technical-review decks are generated by adapting the two
user-provided GAC slide libraries rather than rebuilding their visual system from scratch:

- `GAC-seminar.pptx`: 25-slide navy/teal seminar template;
- `GAC-technical-review.pptx`: 21-slide dark-teal engineering-review template.

`gac-template-map.json` binds every generated slide to a source slide. The generator keeps
all source slides, duplicates the comparator frame once in each deck, and fills that frame
with the retained GCS-versus-macro result. It verifies both source-template hashes and the
GCS evidence schema before writing output.

## Generate

The generator uses the artifact-tool presentation runtime. Point it at an initialized
artifact-tool workspace (for Codex, any presentation workspace produced by the bundled
presentation helpers):

```bash
node paper/scripts/generate_slides.mjs \
  --artifact-workspace /absolute/path/to/artifact-tool-workspace
```

Outputs:

- `compiling-recurrent-agent-workflows-into-guarded-programs.pptx`: 26-slide seminar deck;
- `compiling-recurrent-agent-workflows-into-guarded-programs-detailed.pptx`: 22-slide
  technical-review deck;
- `paper/results/slide_generation.json`: source, evidence, mapping, output hash, and slide
  count manifest.

The generated GCS slide is intentionally scoped: it shows that GCS matches the measured
provider-visible macro's 12/12 exact quality while reducing requests, tokens, observed
latency, and estimated cost. It does not claim superiority over an equally pre-executed
manual macro or across workflow families.
