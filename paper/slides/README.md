# Publication slide generation

**One deck ships:**
`compiling-recurrent-agent-workflows-into-guarded-programs-detailed.pptx`, a
26-slide technical review on the seminar design system.

The [publication shelf](https://rrahimi-uci.github.io/guarded-agentic-compaction/artifacts.html)
publishes this deck alongside the complete paper, HTML article, and benchmark explorer.

It was generated by adapting user-provided GAC slide libraries rather than
rebuilding their visual system from scratch. Two existed:

- `GAC-seminar.pptx`: 25-slide navy/teal seminar template — **retained**, because
  `paper/scripts/restyle_detailed_deck.py` reads its design system at build time;
- `GAC-technical-review.pptx`: 21-slide dark-teal engineering-review template —
  **removed**, because nothing reads it any more.

A 27-slide seminar deck was also generated from `GAC-seminar.pptx`. It was
**removed** too: the shipped deck now carries the same design system, so the two
were largely redundant.

Both removals are declared in `gac-template-map.json` with the hash each artifact
was last verified at and the `git show` command that recovers its bytes;
`validate_artifacts.py` fails if a removal is undeclared, if its hash is missing
from either record, or if a retired artifact reappears as a live output. Removing
`GAC-technical-review.pptx` has one real consequence: `generate_slides.mjs` can no
longer render the deck from its template, so the rebuild path is the one under
"Rebuilding the deck from scratch" below.

`gac-template-map.json` binds every shipped slide to a source slide. The generator kept
all source slides, duplicated the evidence frame for the three-workflow-family result, and
duplicated the comparator frame for the fair-placement and bounded-GEPA result. It verified
the source-template hash, the checked 90-case family summary, the supplementary external
matrix, the GCS replay, and the live optimizer evidence schema before writing output.

## Retitling without the generator

The deck is generated by `generate_slides.mjs`, which needs an external
artifact-tool presentation workspace that is not part of this repository. When the
paper was retitled, the deck therefore could not be regenerated.

`paper/scripts/retitle_slides.py` performs the narrow edit the regeneration
would have made, in place, on the generated deck only:

```bash
python paper/scripts/retitle_slides.py --check   # report
python paper/scripts/retitle_slides.py           # apply
```

It rewrites every title run, drops the title-slide font by 4pt (the new title
is 31 characters longer and at the original size overflowed its box into the
subtitle), adds `<a:normAutofit/>` as a backstop, and sets `dc:title`, which
was the placeholder "Presentation". Re-running is a no-op.

`GAC-seminar.pptx` is never touched — both the generator and the restyle script
verify its hash before reading it.

After editing a deck, refresh its recorded hash in
`paper/results/slide_generation.json` and re-run
`paper/scripts/validate_artifacts.py`.

The Headroom result is a post-generation, one-box update to the workflow-family slide:

```bash
.venv/bin/python paper/scripts/refresh_headroom_ablation_slide.py
```

It asserts the inherited text before replacing it, updates the slide-generation record, and
does not alter the slide's chart or geometry.

## Resynchronizing coordinates after a manuscript change

Each slide's eyebrow names the section, figure, table, or algorithm that slide answers, and
those coordinates go stale whenever the article renumbers. Inserting the Section 2--3 reader
aids added twelve figures and one table, which moved every float after them, so twelve
eyebrows pointed at the wrong exhibit --- the architecture figure was still cited as Figure 1
when it had become Figure 6.

```bash
python paper/scripts/resync_slide_coordinates.py --check   # report
python paper/scripts/resync_slide_coordinates.py           # apply
```

The script does not trust its own table of numbers: every coordinate it writes is asserted
against `paper/open_research/article.aux` first, so a later renumbering fails here loudly
instead of shipping another stale pointer. Build the article before running it.

It also repairs two claims that had drifted from the paper:

- **Slide 12's terminal-edge tally.** The manuscript used to enumerate the dispatch exits as
  one compaction, five baseline returns, and one incident, and now states the invariant
  without the counts. Exactly one edge still compacts, so that box keeps its `1`; the other
  two become `n`. The words `any` and `every` were tried first and do not fit --- the box is
  0.7in wide at 27pt, which leaves about one glyph of usable measure.
- **Slide 13's calibration signals.** The paper now separates them explicitly: the score is
  *fitted* on development groups that were unproductive in any way, while the bound is
  *counted* only from dispatched groups that were wrong.

Text lengths were checked against each edited shape's extent and run size rather than by
opening the deck; no PowerPoint or LibreOffice renderer is available in this environment, so
**open the deck once before presenting it.** The slide-12 incident card is 3.18in x 0.8in at
11pt with no autofit, which is why its replacement text is kept near the original length.

The shipped deck also carries the benchmark-grounded GitHub continuation example on slide 17.
When the pinned generator output is restored, replay the normal `retitle`/`restyle` steps
and then apply the narrow evidence-text transform:

```bash
python paper/scripts/refresh_aha_example_slide.py
```

It is assertive and changes only slide 17. The example is bound to the natural-order
GitHub results and continuation replay by the paper's publication manifest; it is not a
synthetic workflow illustration.

## One design system, not two

The two decks were rendered from two unrelated templates, so they shipped two
visual systems: navy/teal with tracked all-caps labels and three act dividers,
against dark-teal with untracked labels and no act breaks. That is why only one
deck is kept now. `GAC-seminar.pptx` is
the canonical one, so `paper/scripts/restyle_detailed_deck.py` brings the
technical deck onto its formula, in place, for the same reason `retitle_slides.py`
exists — the generator needs a workspace this repository does not carry.

```bash
python paper/scripts/restyle_detailed_deck.py --check   # report
python paper/scripts/restyle_detailed_deck.py           # apply
```

It remaps the palette, tracks the all-caps labels and moves sub-heads to the
muted ink, sets the footer/eyebrow/title boxes to the seminar geometry, inserts
three section dividers built from the seminar's own divider frame (23 → 26
slides), extends each eyebrow with the manuscript coordinate that slide answers,
aligns the dark-slide decorative circles, and moves the five charts from the
off-spec `ppt/slides/charts/` to `ppt/charts/` with a generated workbook each so
PowerPoint can edit their data. Two of those charts cached three data points
against a two-row range; the ranges now match the cached data.

It also shortens the slide headlines. The generated ones ran 52–75 characters,
usually two clauses where the second restates something the body or the eyebrow
already carries — "Six independent rejection points — refusal is the default
output" against a slide whose first card is titled *Qualify & partition*. Each
headline keeps the claim and drops the restatement, landing at 23–43 characters;
the script fails if any headline in a title box exceeds 45. Slide 1 is exempt: it
carries the manuscript title verbatim, and `validate_artifacts.py` checks for it.

Three of those headlines are written by `generate_slides.mjs` rather than
inherited from the template — the two inserted evidence slides and the comparator
slide. Shortening them here is sound because restyle runs *after* generation, so
generate → retitle → restyle reproduces the short form and the generator is
unchanged. One consequence: `validate_artifacts.py` used to pin the
workflow-family slide by its headline, and now pins it by the generator-written
body sentence naming the three families, which no post-generation script edits
and which is the stronger thing to assert.

The eyebrow coordinates are read off the current manuscript rather than copied
from `GAC-seminar.pptx`. That template predates subsections 3.3 and 3.4 and eight
of the tables, so **its own** eyebrow coordinates are stale — `TABLE 1 — EXTERNAL
NESTFUL COMPILER RESULTS` on its slide 17 is Table 4 in the typeset paper, and
`§3.3 AND ALGORITHM 3` on its slide 13 is now §3.5. Nothing ships those stale
references any more, since the deck rendered from that template was retired, but
the template still carries them.

One part of the formula is deliberately not transferred: the seminar renders
display maths as images and numbers the equations in the margin. The technical
deck states the same material as prose and has no equations to number.

Re-running the script is safe — it detects an already-restyled deck and stops.
The transform itself reads the generator's 23-slide layout, so it refuses to run
twice rather than corrupting its own output. `GAC-seminar.pptx` is read for its
design tokens and divider frame against a pinned hash, and never written.

### Rebuilding the deck from scratch

`generate_slides.mjs` cannot run here, so a full rebuild means restoring the
generator's pinned output and replaying the scripted transforms on top of it:

```bash
DECK=paper/slides/compiling-recurrent-agent-workflows-into-guarded-programs-detailed.pptx
rm -f "$DECK"
git show <commit>:"$DECK" > "$DECK"      # generator output, hash-pinned in the manifest
python paper/scripts/retitle_slides.py   # no-op once the title is current
python paper/scripts/restyle_detailed_deck.py
python paper/scripts/finalize_manifest.py
python paper/scripts/validate_artifacts.py
```

Pick the commit whose `paper/results/slide_generation.json` records the generator
output you want as the base — currently
`248eb1f22a1a94c7f4bc6a2e97d26fe89637e2d0ab9ddf5d9203f818a4468643`, which is what
`restyle.rebuild` in that manifest names. Both scripts are deterministic and the
package is written with a fixed timestamp, so the rebuild reproduces the recorded
output hash byte for byte.

Once an artifact-tool workspace is available, run the generator instead and then
replay the two scripts; the restyle asserts against every string it rewrites, so
an upstream rewording fails loudly rather than leaving stale text behind.

## Generate

The generator uses the artifact-tool presentation runtime. Point it at an initialized
artifact-tool workspace (for Codex, any presentation workspace produced by the bundled
presentation helpers):

```bash
node paper/scripts/generate_slides.mjs \
  --artifact-workspace /absolute/path/to/artifact-tool-workspace
```

Outputs:

- `compiling-recurrent-agent-workflows-into-guarded-programs-detailed.pptx`: 23-slide
  technical-review deck, subsequently restyled to 26 slides (see above);
- `paper/results/slide_generation.json`: source, evidence, mapping, output hash, and slide
  count manifest.

The generator also emits the 27-slide seminar deck, which is no longer kept. It
needs `GAC-technical-review.pptx` for the technical deck as well, and that
template was removed — so today the generator can render only the seminar deck it
no longer ships. Restore both retired artifacts from git before running it.

## Current synchronization state

The committed `.pptx` binaries are current with the checked-in generator.
`paper/results/slide_generation.json` now records the same
`generator_sha256_current` as `paper/scripts/generate_slides.mjs`, so there is no active
`regeneration_required` block.

If the generator changes again before the decks are rerendered, the repository records that
drift explicitly instead of hiding it. In that state `slide_generation.json` adds a
`regeneration_required` section naming the stale outputs and the command that clears the
mismatch; `validate_artifacts.py` fails if the generator digest changes and that drift is
not declared.

The `@oai/artifact-tool` runtime is bundled into the Codex primary runtime rather than
published to a public registry. Any initialized artifact-tool workspace produced by the
bundled presentation helpers is sufficient for the render command above.

The generated comparator slide is intentionally scoped: all five arms pass 6/6; GCS and
the independent manual pre-model program tie on requests, interfaces, and input tokens;
official GEPA retains its seed after a bounded live search. The 59-request optimizer cost
is separate from deployment. The slide claims neither cross-family superiority nor a
general failure of GEPA.

The inserted primary-evidence slide reports three distinct real-record workflow families:
compiled and manual programs reach 90/90 exact outcomes versus 89/90 baseline, with
weighted request, token, latency, and cost reductions bound to the source JSON. Its native
editable chart shows per-family token reduction. It explicitly limits transfer to one
repository snapshot and states that fair manual programs remain the runtime baseline.

That slide also carries the paired Headroom result for the PR-outcome and backlog-attention
cohorts: the pinned comparator attempted 240 eligible model-visible JSON payloads, applied
zero transformations, and saved zero tokens. It is reported as a boundary-specific negative
result, rather than an explanation of the compiler's savings or a claim about long contexts.
NESTFUL/API-Bank refusal and the eight other benchmark dispositions remain supplementary.
