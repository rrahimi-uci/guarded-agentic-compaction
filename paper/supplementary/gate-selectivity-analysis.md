# Gate selectivity analysis

This note summarizes the new provider-free analysis in
`paper/results/gate_selectivity_analysis.json`, generated by
`paper/scripts/analyze_gate_selectivity.py`.

## Scope

The goal is not to relabel the current paper as having a demonstrated selective
risk--coverage frontier. The goal is narrower and more honest:

1. inspect every checked-in gate that currently supports the manuscript,
2. separate registered exact-`.05` artifacts from looser-`alpha` or archived artifacts,
3. summarize where the frontier is flat, where it is partial, and where the gate retires
   for insufficient support, and
4. retain concrete negative evidence that explains why the current exact-`.05` story is
   still mostly all-or-none.

## Main findings

### 1. The current exact-`.05` artifacts are still support-threshold gates

Across the **7** current registered exact-`.05` artifacts now checked into the repo:

1. **7/7** are `step_all_or_none` frontiers.
2. **0/7** show a partial risk--coverage frontier.
3. The first non-empty threshold is `0.11` on **5** artifacts and `0.14` on **2**
   artifacts.
4. Once admitted, each of those artifacts jumps directly to full calibration coverage
   (`92/92` groups).

That means the current exact-`.05` evidence is stronger than "no gate at all," but it is
still best described as a **support-threshold gate**, not as a demonstrated selective
admission frontier.

### 2. Partial frontiers exist only in exploratory or looser-`alpha` artifacts

The analysis finds two retained counterexamples to a completely flat story:

1. **Archived live pilot (2026-08-03).**
   - Exact `alpha=.05`.
   - Coverage moves through `10/92`, `15/92`, `78/92`, `90/92`, then `92/92`.
   - This is useful exploratory evidence that the score can induce a frontier.
   - It is **not** score-bearing main evidence because the same pilot does not support the
     current preserved-quality claim.
2. **GCS live study.**
   - Calibrated at `alpha=.10`, not the registered `.05`.
   - Admits `88/92` groups and refuses `4/92`, so it is the only current retained
     partial frontier.
   - The candidate notes retain `6` development unproductive cases and `6` calibration
     unproductive cases, with explicit verifier-side reasons.

This is exactly the right conclusion for the paper text: partial selectivity is **possible
in retained evidence**, but it is not yet the main registered exact-`.05` result.

### 3. Refusal remains a real result, not missing evidence

The external benchmark side is still clean:

1. **NESTFUL:** maximum observed family support `26` versus `92` zero-violation groups
   required.
2. **API-Bank:** maximum observed family support `8` versus `92` required.

Both therefore remain legitimate support-shortfall refusals rather than near-miss positive
results.

### 4. Retained negatives explain why the current frontier is flat

The new analysis also summarizes retained failure evidence outside the registered current
artifacts:

1. The archived projection-failure bundle in
   `paper/results/github_workflow_families/pr_outcome/pilot_v1/failed_attempt_projection_2026-08-05.json`
   records `13` `composite_projection_failed` events, `5` `range:pr.body_excerpt`
   rejections, and three individual hull rejections.
2. The pre-fix live failure in
   `paper/results/github_natural_replication/failed_attempt_2026-08-03.json`
   records `0` compiler-eligible traces where `116` were required.
3. The fifth multirepo repository, `pytorch/pytorch`, still fails closed under the strict
   frozen-candidate gate rather than broadening coverage after seeing the held-out class
   mix.

These are useful negatives, but they are not a substitute for a natural-error
development/calibration design that directly produces a discriminative exact-`.05`
frontier.

## Interpretation

This analysis helps the paper in two ways:

1. It sharpens claim hygiene. The manuscript can now point to a dedicated artifact rather
   than describing the gate behavior only in prose.
2. It shows that the current blocker to a `95`-style review is empirical, not editorial:
   the repo still needs a richer exact-`.05` selective frontier on natural error, not just
   a cleaner explanation of the existing gate.

It does **not** by itself justify a higher top-line score. The correct reading remains:

- current exact-`.05` gates are mostly all-or-none,
- partial selectivity exists only in exploratory or looser-`alpha` retained artifacts,
- support-shortfall refusal is real and important, and
- a defensible move toward the mid-90s still requires new experiments.
