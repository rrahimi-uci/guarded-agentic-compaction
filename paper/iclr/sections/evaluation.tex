\section{Experimental Setup}
\label{sec:setup}

\paragraph{GitHub workflows.}
Every sample begins with one issue or pull-request number from a pinned public
snapshot~\citep{githubissuesdataset}; the agent must make read-only calls and return exact,
source-grounded fields. The three primary families use
132 discovery records each, from whose exact traces a stable hash draws 16
train, 8 dev, and 92 calibration groups ($\mathcal{K}$; the rest stay unused), and 30
balanced held-out records, with live provider calls, each pairing a read-only
evidence path with an exact answer contract (a category, a title, and a
verbatim excerpt; \cref{tab:benchmark-glance}, \cref{app:detail}). The
exact-trace filter is inert here (130--132 of 132 exact) but is a selection
step; \cref{app:limits} shows where it binds.

\paragraph{Cross-repository extension on newer records.}
A narrower two-read PR-outcome task spans five frozen public repositories.
Held-out records are newer than discovery records but inside the same frozen
snapshot, which every artifact pins; selection is sealed before provider calls,
and repositories without an admitted artifact stay in the result. A balanced
rerun on three repositories controls the class mix.

\paragraph{Public benchmarks.}
On BIRD~\citep{li2023bird} a live SQL agent runs over pinned read-only
databases (\cref{app:bird}). NESTFUL~\citep{basu2025nestful} and AppWorld's gold
solutions~\citep{trivedi2024appworld} supply executable traces, plus released
AppWorld agent runs; no model runs on these two, so no efficiency claim. API-Bank and BFCL v4~\citep{li2023apibank,patil2025bfcl}
behave like NESTFUL (\cref{app:external}).

\paragraph{Provider configuration.}
The primary studies use OpenAI \code{gpt-5.6-luna} via the \code{openai-agents}
Responses interface~\citep{openai2026agents} at reasoning effort \code{low},
priced at list rates~\citep{openai2026pricing}; the
replications use \code{gpt-6-luna} and Anthropic \code{claude-sonnet-5} under
the same settings (\cref{app:config}). Conditions within a family differ in
structure alone.

\paragraph{Conditions, metrics, and statistics.}
Each GitHub family compares the unchanged baseline $B$, the compiled artifact,
and a hand-written pre-model program on the same records, so comparisons are
paired. Quality is exact task-contract satisfaction; resources are requests,
interfaces, tokens, latency, and estimated cost; tests are paired exact
McNemar~\citep{mcnemar1947}, bootstrap intervals~\citep{efron1993bootstrap},
and Wilcoxon signed-rank~\citep{wilcoxon1945}, with the Bonferroni term of
\cref{eq:cp} the only guaranteed multiplicity control.
