Tool-using agents pay for a model decision at every tool boundary. When a
workflow recurs, an engineer can hand-write a program for its opening, but must
write, check, and maintain it, and recurrence alone does not make it safe.
Guarded agentic compaction (\method) automates that step safely: it compiles an
agent's opening read\nobreakdash-only calls into a
deterministic program only when every argument is grounded in observed state,
every effect is declared read\nobreakdash-only, and the program starts at the
first step; otherwise it refuses, and admits one only when enough independent
calibration examples support a finite-sample error bound. The target is the
program an engineer would write, found without being told the workflow. On three
GitHub workflows the compiled agent satisfies 90/90 held-out task contracts, as
hand-written programs do, against 89/90 for the unchanged agent, with 66.6\%
fewer model requests. Against
adapted offline Agent Workflow Memory on 1,362 fresh records, five of six
workflow and model cells meet a five-point accuracy noninferiority margin at
36.9--79.1\% lower estimated cost. On BIRD
text-to-SQL, a schema-first opening compiles on 26/31 databases; NESTFUL,
API-Bank and BFCL tool-trace candidates are refused for insufficient calibration support;
AppWorld's admitted program is rarely eligible for ReAct-style agents. Most
bounds cover replay on selected populations; one covers final answers: no
failure on 132 pull requests opened after the snapshot (90\% upper bound
0.0173).
A later study samples one pull request per author before any outcome filter and
grades final task contracts: 3 misses in 760 groups across four repositories, each
admitted by its own frozen candidate (bounds 0.023--0.042, registered grid).
Replay bounds do not cover unfiltered deployment, two primary families miss the
selection-adjusted 5\% target, and we claim no benefit on adaptive tasks or from
a learned dispatch gate.
