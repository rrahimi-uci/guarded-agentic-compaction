\section{Introduction}

The standard agent loop pays for a model decision at every tool
boundary~\citep{yao2023react}, which is valuable while a workflow is novel but
redundant when an agent repeats the same opening across runs; read\nobreakdash-only
openings of two or more calls start 4--41\% of released trajectories per corpus
(\cref{app:prefix-census}). Removing that decision is not ordinary caching: a
tool argument may depend on an earlier result, a repeated sequence may cross an
approval or write, a read\nobreakdash-only tool may hide an effect, and
replaying the same outputs may still change the final answer. Recurrence
therefore shows where a deterministic program could save work, not permission
to substitute one. An engineer who knows the workflow can write that program;
\emph{guarded agentic compaction} (\method) automates writing it, substitutes it
only where it can justify doing so, and refuses elsewhere. Success is recovering
the hand-written program safely, not beating it.

Consider GitHub issue triage, one of three workflow families we study: given
an issue number from the public \code{huggingface/datasets} snapshot, the agent
returns a label-based category, the issue title, and an exact evidence excerpt.
On held-out issue \#4420 the agent calls \code{record(4420)}, passes the
\emph{returned} \code{record.issue\_number} to \code{labels} and to
\code{comments}, and sets the comment \code{limit} to 100. All 132 discovery
runs (the traces the compiler learns from) take this three-read route, 130
with \code{limit=100} and two with \code{limit=1}, so a recurrence-only optimizer would compile all three reads.
\method refuses that region because \code{limit} has no \emph{witness}: it is
neither a constant across runs nor computable from the issue number or an
earlier result (\cref{fig:provenance}). The two-read prefix
\code{record}~$\rightarrow$~\code{labels} survives, and the agent still chooses the limit and writes the answer. The
refusal is a grounding decision, not a quality gain: recurrence-only replay of
all three reads matches \method's 30/30 held-out answers with one fewer request
(\cref{sec:res-primary}). An earlier admitted three-read program passed replay
yet dropped a URL from issue \#6602's final answer (\cref{app:limits});
grounding, replay fidelity and answer quality are distinct obligations.

The classical precedent is trace compilation: Dynamo~\citep{bala2000dynamo}
and tracing just-in-time compilers~\citep{gal2009tracejit} compile a hot path
behind \emph{guards} and fall back when one fails, as
deoptimization~\citep{holzle1992deopt} restores unoptimized execution. Agent
traces share that structure, but \method compiles only \emph{initial}
read\nobreakdash-only prefixes (\cref{eq:prefix}), and substitution adds three
obligations: every tool argument must be \emph{grounded} in observable state;
declared \emph{effects} must permit speculative execution, because the
``interpreter'' calls the outside world; and the residual error rate, being
statistical, needs a finite-sample bound before a program is admitted.
\Cref{fig:pipeline} shows where \method enforces each. Our contributions are:

\begin{enumerate}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
  \item A compile-or-refuse criterion that admits an initial read-only prefix
only when its arguments are grounded, its effects are declared read-only, and
it starts at the agent's first step, and only when enough calibration
examples, assumed independent, pass to meet a standard exact binomial bound
(\cref{alg:compile,alg:calibrate,prop:admission}).
  \item Live-provider measurements on three GitHub workflows and the BIRD
text-to-SQL benchmark, where the compiled agent uses fewer model requests at
similar accuracy, plus re-discovery on two further models and
one-at-a-time safeguard ablations (\cref{sec:res-primary,sec:res-bird,sec:res-more}).
  \item Measured refusals and scope: NESTFUL, API-Bank and BFCL v4 lack
calibration support, AppWorld's admitted program is almost never eligible on
ReAct or plan-and-execute trajectories, and most bounds cover replay rather
than final answers (\cref{sec:res-refusal,sec:res-more}).
\end{enumerate}
